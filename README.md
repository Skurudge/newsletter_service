# Мой учебный проект Python "Django_one"

## Описание:

Проект представляет собой развивающийся маркетплейс "Skystore" — платформу для хранения, публикации и продажи плагинов и примеров кода [catalog:views]. Веб-приложение построено на базе фреймворка Django с использованием архитектурного подхода CBV (Class-Based Views), СУБД PostgreSQL и стилизации интерфейса на Bootstrap [catalog:views, config:settings]. В систему интегрирована продвинутая система оптимизации производительности на базе СУБД Redis, полноценная ролевая модель доступа (RBAC), модерация контента, контентный раздел (блог) и продвинутые механизмы валидации данных [catalog:forms, catalog:views, catalog:services, config:settings, blog:views].

Редактирование содержания проекта сторонними пользователями не предусмотрено.

## Установка:

1. Клонируйте репозиторий:
   ```bash
https://github.com/Skurudge/newsletter_service
   ```
2. Настройте переменные окружения в файле `.env` в корне проекта (укажите параметры подключения к PostgreSQL, `SECRET_KEY`, а также адрес брокера `REDIS_LOCATION`) [config:settings].
3. Убедитесь, что у вас установлен и запущен локальный сервер **Redis** (по умолчанию доступен на `127.0.0.1:6379`) [config:settings].
4. Сгенерируйте и примените миграции базы данных [catalog:models, users:models]:
   ```bash
   python manage.py makemigrations
   python manage.py migrate
   ```
5. Настройте группы пользователей и права доступа [catalog:management:commands:create_groups]:
   ```bash
   python manage.py create_groups
   ```
6. Наполните базу данных тестовыми материалами с автоматической привязкой к системному владельцу [catalog:management:commands:add_products]:
   ```bash
   python manage.py add_products
   ```

## Использование:

1. Запустите локальный сервер разработчика: `python manage.py runserver`.
2. Перейдите по адресу **`http://127.0.0.1:8000/`** в вашем веб-браузере.
3. Доступ к интерфейсу и кнопкам управления динамически меняется в зависимости от прав и роли авторизованного пользователя [catalog:templates:home, catalog:templates:product_detail, blog:templates:blog:blogpost_list].

### Разработанные объекты, функции и модули:

* **Интеграция Redis и оптимизация скорости (Задание 1):**
  * В качестве брокера для кэширования к проекту подключена СУБД **Redis** с использованием пакетов `redis` и `django-redis` [config:settings].
  * Конфигурация кэширования вынесена в `settings.py` и настроена на работу с изолированной базой данных Redis [config:settings].
* **Кэширование на уровне представлений (Задание 2):**
  * Внедрено кэширование детальной страницы информации об одном продукте (`ProductDetailView`) с помощью декоратора `cache_page` [catalog:views]. Время жизни кэша (TTL) составляет 15 минут (900 секунд) [catalog:views], что значительно снижает нагрузку на базу данных при частом просмотре карточек товаров.
* **Сервисный слой и низкоуровневое кэширование (Задание 3, Задание 4):**
  * Создана выделенная сервисная функция `get_products_by_category` для обработки логики получения продуктов [catalog:services].
  * Функция реализует низкоуровневое кэширование списков продуктов по уникальным ключам вида `category_{id}` [catalog:services]. 
  * При отсутствии данных в Redis выполняется один тяжелый запрос к PostgreSQL, результат которого сохраняется в кэш с заданным TTL [catalog:services]. При повторных запросах данные мгновенно извлекаются из оперативной памяти.
  * Реализовано отдельное представление `CategoryProductListView` и соответствующий HTML-шаблон `category_products.html` для вывода отфильтрованных по категориям товаров через созданный сервис [catalog:views, catalog:templates:category_products].
* **Ролевая модель доступа и права:**
  * В модель продуктов добавлено поле `is_published` для контроля статуса модерации [catalog:models].
  * Разработаны роли **Модератор продуктов** (управление публикацией, удаление товаров) и **Контент-менеджер** (полное управление блогом) [catalog:management:commands:create_groups, catalog:views, blog:views].
* **Механизм владения объектами:**
  * Модель продукта связана с моделью пользователя через поле `owner` [catalog:models]. Изменять и удалять товар разрешено только его прямому владельцу или профильному модератору [catalog:views].
* **Кастомная система атентификации (Приложение `users`):**
  * Реализована кастомная модель на базе `AbstractUser` с авторизацией по `email` и дополнительными полями (аватар, телефон, страна) [users:models, users:views]. Настроена автоматическая отправка приветственных писем при регистрации [users:views].

### Тестирование:

* Тестирование механизмов оптимизации выполняется путем замера скорости повторной загрузки карточек продуктов и страниц категорий, а также мониторинга кэш-ключей в консоли Redis.
